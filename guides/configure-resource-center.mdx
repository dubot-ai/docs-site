Configure one Copilot for your workspace, test it on a representative product page, and publish the complete experience.

## Choose the first user task

Start with something specific: understand a bill, invite a teammate, or complete a setup step. Choose an outcome you can observe and a point where the user should take over. Use three to five relevant entries per page rather than reproducing your Help Center navigation.

## Configure Content

Open **Copilot** and select **Content**. Put shared resources in **All pages**, then add overrides for exact paths or path prefixes. Pin the most useful page-specific task first and hide inherited resources that do not help on that route.

<Note>
  For a page and its descendants, enter the route root and choose **Prefix**. Do not append `/*`; those characters are literal. Test both the root and a descendant in the host product. Selecting an override in the editor does not prove the live URL matches.
</Note>

Add a **Prompt** for a common task. Give its chip a short outcome label such as “Set up billing” and write the full request the agent should receive. Selecting the chip starts a conversation. You can also add reviewed guides, Help Center articles, video embeds, hyperlinks, host callbacks, and an MCP connector where available.

Do not pin the same inherited item again. Use an override to change relevance, not to create duplicate cards. Verify every callback and guide in the host product before making it a recommended path.

## Configure the Copilot Agent

In **Agent**, configure the reserved agent's prompt, knowledge scope, and Skills. Skills supply the agent's available actions. This agent saves and publishes with Copilot and has no independent placement or version history.

Ask is always available in the authoring experience. Enable file uploads only when useful for the task and choose the supported file types. **Let users point at things on the page** controls page-element attachments.

The current route and available Copilot items are supplied at runtime. The agent should ask only for information that the page, knowledge, and its tools cannot provide.

### A task-focused starting prompt

```text
Help the user complete the task they came here to do. Use the current page and available product context before asking for more information.

Answer a specific question directly. For a task, offer the shortest supported path: explain it, show the next step, or perform an available action. Use only configured Skills, actions, guides, and callbacks. A resource card is not permission to call a tool.

Preserve user-owned steps. Ask for required confirmation before a consequential action, and verify the resulting product state before saying the task is complete.

If the next step is unavailable, say what you found and offer a working resource or configured support path. Keep the first reply concise.
```

Adapt this prompt to your product and available tools. It describes the intended behavior; testing must establish which tasks your configuration can complete.

## Configure Settings

Set the panel title, welcome copy, and composer placeholder. A useful starting point is “What would you like to get done?” with “Ask a question or describe a task.” Choose Floating, Injected, Auto-open, or Programmatic as the trigger.

Host callback cards invoke matching handlers registered through `Dubot.init({ resourceCenterCallbacks: [...] })`. They are separate from agent-callable actions. Use [SDK surfaces](/sdk/surfaces#copilot) for `openCopilot()` and `closeCopilot()`.

## Test and publish

<Steps>
  <Step title="Preview the home and page override">
    Save the draft, then inspect the composer, prompt chips, resource ordering, and inherited content in Preview.
  </Step>
  <Step title="Exercise a real task in Test">
    From **Agent**, start a browser-extension Test session on a representative product page. Test a typed request, a prompt chip, a knowledge-backed answer, and every recommended guide or callback. Check allowed attachments and history when relevant.
  </Step>
  <Step title="Check handoffs and the result">
    If the task launches Guidance, verify Show or Do behavior, user-owned steps, Stop and Resume where applicable, and the observed final state. A successful launch is not a completed task.
  </Step>
  <Step title="Publish the dependencies and Copilot">
    Publish the required actions, Skills, guides, and Guidance configuration for Production. Then use the Copilot page's **Publish** action. Its reserved agent is included in the same version.
  </Step>
  <Step title="Verify the published experience">
    Repeat the safe task on an approved Production origin. Confirm the correct route content, working task paths, and expected activity or conversation records.
  </Step>
</Steps>

**Preview** and extension Test use the saved draft; ordinary users receive the published version. If they differ, check publication before changing a route rule. **Unpublish** removes Copilot from Production; archiving also removes it from Test.
