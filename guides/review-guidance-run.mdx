Use a representative Guidance run as the starting point for a reusable guide. A completed run alone does not prove that every step was correct.

## Review the run

Open **Guidance**, then **Analytics**. Choose a relevant theme and session. Inspect pages, steps, targets, user-owned work, tool activity, errors, and final state. A run can have multiple themes, so theme totals can overlap.

Select **Save as guide** on a suitable run. The draft retains its source-run link. It copies the resolved mode and projects user-owned stages into editable handoff instructions. Historical runs with an unknown mode need an explicit selection.

## Edit the guide

Review these fields before saving:

| Field | What to check |
| --- | --- |
| Title | Names the user outcome clearly |
| Goal | Defines the result and stopping point |
| Start condition | Describes where and when the guide should begin |
| Trigger phrases | Phrases that should select this guide once published |
| Show or Do | Chooses whether the user operates the interface or Dubot may perform agent-owned stages |
| Guide body | Plain-language steps, required user handoffs, and observable completion evidence |

Generalize accidental IDs, recovery narration, and one-off values from the source run. Preserve the important user-owned stages. The current guide body is plain text; do not recreate a typed Message/Perform/Indicate/Ask sequence or save CSS selectors as targeting instructions.

Follow [Write guides that work](/guides/write-guidance-guides) for concise authoring. Use the extension's available authoring workflow when reviewing the journey against the live product.

## Test and publish

<Steps>
  <Step title="Save and test the draft">
    Test on a safe product page. Confirm the start condition, resolved mode, each user handoff, Stop and Resume behavior where applicable, and observed final state.
  </Step>
  <Step title="Publish the reviewed guide">
    Save the reviewed body and explicit mode, then publish the guide. A newer draft does not replace the published version until you publish it. Guidance must also be enabled and published for that environment.
  </Step>
  <Step title="Offer it in Copilot">
    Add the published guide to **All pages** or a relevant page override in **Copilot**, then publish Copilot. Exercise the actual launch and complete the journey on an approved origin.
  </Step>
</Steps>

Re-test after meaningful host-interface changes. Compare guide outcome with the actual product result; a tooltip, Skip, or successful launch does not establish that required work is complete.
